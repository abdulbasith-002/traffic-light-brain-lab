01 / The big idea

Think of it like a very careful crossing guard

A traffic controller receives information, follows rules, and changes the lights in a safe order. In this project, digital hardware logic acts like the crossing guard's brain.

🚗 🚕 🚙

1. Notice the traffic

A sensor or AI camera could estimate how many vehicles are waiting. More vehicles can mean a longer green-light time.

🧠

2. Make a decision

The controller groups traffic into low, medium, or high density. The example code below uses simple thresholds to demonstrate this.

🚦

3. Follow the sequence

A finite-state machine (FSM) changes between traffic phases in a planned order instead of switching randomly.

02 / Five simple steps

From cars to lights

The whole system can be understood as five small jobs.

1

Read the input

Get a vehicle count from a sensor, simulator, or upstream AI system.

2

Classify density

Decide whether traffic is low, medium, or high.

3

Pick a duration

Choose how many clock cycles the green phase should last.

4

Count the time

A timer counts clock edges until the phase ends.

5

Change the lights

The FSM switches to yellow and then red in its programmed order.

06 / Code explained

Meet the project modules

📊 density_logic.v

Looks at the vehicle count and labels it low, medium, or high. The thresholds are example values and should match your final source code.

⏱️ traffic_timer.v

Counts clock cycles. A clock is like a steady tick-tock that helps digital hardware keep time.

🧭 traffic_fsm_final.v

The FSM remembers the current traffic phase and decides the next phase when the timer finishes.

🔌 traffic_system_top_final.v

Connects the smaller modules together and exposes inputs and outputs at the top level.

🧪 traffic_system_tb_final.v

A testbench provides pretend inputs, advances the clock, and lets you inspect the outputs in simulation.

📈 Waveform

A waveform is a timeline of signals. It helps you see if red, yellow, green, and timer signals change when expected.
